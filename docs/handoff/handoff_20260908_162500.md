## 1. 本次迭代核心攻关与问题解决

### 1.1 住宿费五大必填字段缺失根本原因排查与端到端补齐
- **痛点现象**：用户在官方费用明细界面编辑保存住宿费记录（如天津美悦酒店 ¥1,840）时，系统弹出红框报错：“1. 单价必填”、“入住日期必填”、“离店日期必填”、“出差城市必填”、“住宿城市类型必填”，且酒店名称为空。
- **根因剖析**：
  1. **类型判断 category 陷阱**：在 `saveSingleExpenseItemApi` 中，历史代码使用了 `targetTypeConfig.category === 'HOTEL'`。但元年云数据字典中，所有差旅费用类型常量的 `category` 统一为中文 `'差旅费'`，导致住宿、飞机、火车的判断全部失效，直接跌入 `else`（出租车默认分支），导致住宿专用字段完全未被设置；
  2. **城市与住宿区分级联缺失**：住宿费的单价、入住/离店日期、城市、IV住宿区分存在严格的模型级联关系。
- **重构与强化方案**：
  1. 采用强唯一标识进行枚举比对：`targetTypeConfig.code === EXPENSE_TYPES.HOTEL.code || targetTypeConfig.id === EXPENSE_TYPES.HOTEL.id || row.type === 'HOTEL'`；
  2. **入住与离店日期 (`CHECK_IN_DATE` / `CHECK_OUT_DATE`)**：依据发票日期与对齐到的波次起止日期智能回填（如天津波次 2026-07-21 ~ 2026-07-25）；
  3. **住宿天数 (`STAY_DAYS`) 与单价 (`UNIT_PRICE`)**：根据起止日期精确计算晚数 `stayDays`（如 4 晚），按 `totalAmount / stayDays` 计算每晚单价（¥1,840 ÷ 4 = ¥460/晚），并构造包含 `currencyId` 与 `currencySymbol` 的完整货币对象写入；
  4. **出差城市 (`CITY`) 与住宿城市类型 (`F_ZSC_DEF_001`)**：动态调用 `/fssc/dim/dimObject/getDimObjectAccessTree` 获取合法城市维表对象；并联动计算“境内-北上广深” (`035a402fee2345af7f1906ec05cc0000`) 与“境内-其他” (`035a403ff62345af7f1906ec05cc0000`)；
  5. **实机 API 验证**：针对真实记录 `048634c464dd857060cdf741d9320001` 调用 `validateAndSaveExpenseRecord`，原 5 大必填校验错误已 **100% 全部消除**。

### 1.2 费用记录错误检测、智能纠偏与 HITL (人在回路) 确认机制
- **错误发现能力 (Detection)**：
  - Agent 拉取发票与费用记录时，自动调用底层规则接口 `getExpenseTypeFieldRuleListAndAllValueVO` 获取字段校验规则；
  - 结合发票 OCR 原生明细（销售方、金额、日期、明细品目）与多模态排期计划进行交叉验证，识别出必填项缺失、金额与单价冲突、超标风险等问题。
- **智能纠偏能力 (Auto-Correction)**：
  - 依据行程多模态排期自动对齐波次起止日期与酒店名称；
  - 自动将时间窗口内的过路费合并绑定至出租车记录（1笔费用多张发票）；
  - 在 A2UI 界面中以醒目的黄色提示条（`missingFields`）和明细预览表格，直观指引用户核对。
- **入库前用户确认规约 (HITL 核心铁律)**：
  - **核心铁律守卫**：所有推断与纠错成果仅存在于内存与前端声明式 A2UI 卡片中；
  - **入库操作（写库保存为未提交草稿）必须由用户在 A2UI 界面上点击“🚀 一键批量保存”或在对话中下达明确确认指令后才会真正执行**；
  - **绝对禁止未经确认静默写库**，且智能副驾**绝对禁止调用审批流提交接口**（审批流提交由用户人工复核后在官方界面手动点击完成）。

### 1.3 A2UI 关联项目输入框宿主系统维表实时检索与下拉建议
- **需求**：用户在 A2UI 表单的“关联项目”输入框键入时，需实时调用宿主系统项目维表接口，以便精准选择标准项目名称与编号。
- **工程落地 (`src/ui/webmcpA2Ui.ts`)**：
  1. 在声明式 A2UI 表单的 `case 'input'` 节点渲染器中，针对 `node.bind === 'projectName'` 或 `node.props?.isProjectSearch` 注入动态搜索能力；
  2. 挂载 250ms 防抖监听器，输入时调用 `/fssc/dim/dimObject/getDimObjectAccessTree` 接口动态模糊查询系统项目维表；
  3. 悬浮展开半透明阴影下拉菜单，展示 `[项目编号] 项目名称`（例如输入“住友理工”即实时弹出 `X2607-001 住友理工集团网络整合调研`）；
  4. 支持点击即选即填、双向绑定至 `ast.model.projectName`，并驱动费用说明与预算归属即时重算联动。已在用户实机浏览器中截图验证。
