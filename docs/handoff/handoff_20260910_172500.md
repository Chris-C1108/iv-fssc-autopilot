## 1. 本次攻坚背景与用户诉求

在费用记录批量编辑弹窗（`#expense` 模块）的实测落地中，用户在批量保存时遇到两大致命拦截，并提出了交互体验改进需求：
1. **乐观锁版本冲突报错**：
   - 错误表现：用户修改费用类型或批量编辑保存时，控制台或气泡弹窗报错 `⚠️ 保存完成: 成功 0 笔，失败 1 笔: 版本不一致，您获取的，请刷新`。
2. **“超标说明必填”后端刚性拦截**：
   - 用户敏锐洞察：“超标应该是住宿费超出标准后触发的必填字段”。

3. **去外驻化与社员名动态嗅探**：
   - 彻底删除业务预设中突兀的 `[外驻+人名]`，增加并默认使用 `[当前社员名]-[项目号]` 规范说明。
4. **反人类筛选外提示清理**：
   - 彻底移除底部状态栏突兀奇怪的 `⚠️ 筛选外有 8 笔被选 (点击仅保留筛选内)` 提示。

## 2. 核心攻坚成果与技术细节

### 2.1 攻克乐观锁 `version: 0` 覆盖缺陷（彻底根治“版本不一致”）
- **缺陷根因**：
  在 `src/services/expenseService.ts` 的 `batchUpdateExpenseRecordsApi` 中，当费用类型发生变更调用 `initExpenseRecordWithTypeApi` 进行内存模型初始化时，该接口返回的通用模板默认包含 `version: 0`。旧逻辑使用了无条件覆盖：
  ```typescript
  if (initRes.version !== undefined) version = initRes.version;
  ```
  这直接将从数据库实时获取的最新真实乐观锁版本号（如 `version: 6`）粗暴覆盖回 `0`！在提交持久化时，后端检测到 `version: 1` 与数据库的 `version: 6` 不一致，触发乐观锁拒绝，报错 `版本不一致，您获取的，请刷新`。
- **修复方案**：
  改为严格单调递增守护，锁定来自真实数据库 `ruleData.version`：
  ```typescript
  if (initRes.version && initRes.version > version) version = initRes.version;
  ```

### 2.2 攻克“超标说明必填”后端业务拦截（用户直觉 100% 命中）
- **业务机制**：
  对于住宿费（`HOTEL`），多间房发票合并开具时（例如 3 间 4 晚），系统按天除算计算 `UNIT_PRICE = AMOUNT / STAY_DAYS = 1066.37`，超出城市标准限额（¥700），系统内部规则引擎触发 `OVER_STANDARD: true`，并将字段 `OVER_STANDARD_DESCRIPTION` 动态标记为 `required: true`。
- **自愈与必填守卫**：
  在 `src/services/expenseService.ts` 中：
  1. 在 `DynamicExpenseFieldValues` 与 `extractSavedDynamicFields` 中全量纳管 `overStandardDescription` 字段；
  2. 在执行保存组装行数据前增加超标自愈拦截：
     ```typescript
     const isOverStandard = ruleData.ruleList?.find(r => r.id === 'OVER_STANDARD')?.value === true ||
                            ruleData.ruleList?.find(r => r.id === 'OVER_STANDARD_DESCRIPTION')?.required === true;
     if (isOverStandard && !dyn.overStandardDescription) {
       dyn.overStandardDescription = dyn.remark || '项目出差业务需要，就近入住';
     }
     ```
  3. 当检测到超标或字段必填时，自动注入合理合规理由，彻底消除后端阻断。

### 2.3 去外驻化与当前社员名动态嗅探
- **社员名自适应**：
  在 `src/ui/batchEditExpenseModal.ts` 中升级 `detectCurrentEmployeeName`，优先从 `sessionStorage.getItem('console_userName')` 与 `ecs_currentUser` 动态读取（如 `"陈浩（ITS）"`），并通过正则清洗剥离括号后缀得到真实社员名（`"陈浩"`）。
- **预设重构**：
  - 彻底清理 `[外驻:人名]` 相关按钮与切换逻辑；
  - 默认模板升级为 `[${employee}]-[${project}]-[${remark}]`，实时预览直接回显为标准规范 `[陈浩]-[X2607-001]`。

### 2.4 清理反人类的筛选外提示
- 优化底部状态栏渲染逻辑，移除了底部不合时宜、打扰用户的 `⚠️ 筛选外有 8 笔被选 (点击仅保留筛选内)` 标签，保持简洁利落。
