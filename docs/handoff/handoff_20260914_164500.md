## 1. 变更背景与需求总览

用户在批量修改费用信息界面中提出了三项高频体验与核验诉求：
1. **费用类型列状态中文化**：彻底清剿页面中残留的 REIMBURSE、ALREADY_REIMBURSE 等英文状态代码，统一使用标准规范的中文（未报销、报销中、已报销）；
2. **费用类型列多维筛选支持**：在费用类型的表头漏斗筛选中，新增支持对【报销状态】与【报销单类型（差旅·BC / 经费·BJ）】的直接筛选，并支持多维复合逻辑；
3. **发票类型列悬浮照片预览**：在发票类型列的单元格内添加图标微按钮（🖼️），鼠标悬浮即可弹出浮窗展示真实发票原件照片，**浮窗位置经过严格几何碰撞检测，绝对不遮挡鼠标光标**。

## 2. 核心架构与工程实现

### 2.1 状态枚举中文清洗与规范化 (
ormalizeExpenseStatus)
- **根因**：系统底层枚举不仅有 NO_REIMBURSE，还有 REIMBURSE（报销中）和 ALREADY_REIMBURSE（已报销），旧代码因未命中直接回落输出了原英文字符串；
- **解法**：在 xpenseService.ts 中封装并导出通用的 
ormalizeExpenseStatus，对所有状态输入进行全量清洗规范化：
  - NO_REIMBURSE / UNREIMBURSED / DRAFT ➔ 未报销
  - REIMBURSING / REIMBURSE / IN_REIMBURSE ➔ 报销中
  - ALREADY_REIMBURSE / ALREADY_REIMBURSED / REIMBURSED ➔ 已报销
- 在接口抽取（etchExpenseRecordsWithInvoiceDetails）、分组聚合（groupExpenseRows）和 UI 渲染（enderGroupRowsHtml）三层实施闭环清洗。

### 2.2 费用类型列“三维交叉复合筛选引擎”
- **数据源扩展**：getGroupColumnValues(group, 'expenseTypeName') 同步输出：
  [类型名, '状态: ' + status, '单据: ' + flowName]
- **复合筛选逻辑（维度内 OR，维度间 AND）**：
  在 getFilteredGroups 中：
  - 若用户勾选了【报销状态】（如 状态: 未报销），则当前行必须符合选中的状态之一；
  - 若用户勾选了【单据类型】（如 单据: 差旅·BC），则当前行必须符合选中的单据之一；
  - 若用户勾选了【费用类型】（如 住宿费（宿泊代）），则当前行必须符合选中的类型之一；
  实现了精准的“未报销且属于差旅·BC的住宿费”交叉筛选；
- **分组卡片式 UI**：
  在 enderFilterValListHtml 中，选项自动分三段渲染，配以 📋 报销状态、📑 报销单类型、🏷️ 费用类型 分组小标题，在实时搜索与全选时完全自适应。

### 2.3 发票原件照片悬浮预览防遮挡算法
- **发票附件 ID 穿透提取**：
  在并发抽取发票时，自动从 inv.attachmentId || inv.attachId || inv.fileId || inv.invoiceAttachmentId || invItem.attachmentId || attachList[idx]?.attachmentId 提取真实发票照片附件 ID，并注入发票明细对象；
- **发票类型列微按钮**：
  在发票类型标签右侧渲染微型 🖼️ 按钮（.yn-bem-invoice-photo-btn），若存在发票附件则高亮并带有悬停动效；
- **智能防遮挡碰撞算法**：
  - 全局单例浮窗 #yn-bem-invoice-preview-popover 挂载在最外层模态容器中；
  - 核心属性声明 pointer-events: none，彻底杜绝浮窗夺取鼠标焦点引起的闪烁与遮挡；
  - 水平定位：默认放置于鼠标光标右侧 24px（left = clientX + 24）；若右侧超出屏幕边缘，则平滑切换至鼠标光标左侧 24px（left = clientX - popWidth - 24）；
  - 垂直定位：以光标为基准垂直居中限位在视口内（	op = Math.max(16, Math.min(window.innerHeight - popHeight - 16, clientY - 120))）；
  - 支持发票照片即时加载动画，并提供“在新标签打开 ↗”链接（pointer-events: auto）。
