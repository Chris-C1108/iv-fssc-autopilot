## 1. 核心需求与背景

用户反馈：
> “发票详情中才能查看到 例如 出租车缺少上下车时间等，当前并未能实现”

在发票夹外层列表表格中，仅展示了“发票类型、发票代码、发票号码、开票日期、价税金额”等通用汇总列，缺少上下车时间、里程等关键列。出租车发票经元年 OCR 识别后，上下车时间常常识别为空字符（`""`），但这些缺失字段必须点开每张发票的“查看”或“修改”弹窗才能肉眼确认，用户难以在列表层面快速排查，导致后续生成费用记录时行程对齐失败。

---

## 2. 核心架构设计与关键技术突破

### 2.1 详情穿透与后台异步静默预取机制
1. **React Fiber 原生 DataId 提取 (`getRowDataId`)**：
   - 外部表格行未暴露数据主键，插件通过 React Fiber 遍历 (`__reactInternalInstance...`) 获取底层 `BO_DATA_ID.value`，保证 100% 精准对应每张发票的真实数据库主键。
2. **多源鉴权凭据自适应管道**：
   - 建立了双通道凭证获取机制：优先使用宿主网络拦截器（`hookInvoiceDetailNetwork`）捕获的最新请求头；若尚未触发 XHR，自动安全回退至宿主窗口的 `sessionStorage.getItem('ecs_TOKEN')` / `sessionStorage.getItem('ecs_token')` 以及 URL 参数 `TOKEN`，确保预取详情 100% 鉴权成功。
3. **轻量并发静默预取与全局详情缓存 (`invoiceDetailCache`)**：
   - 针对列表中出租车发票，在初次渲染或分页变动时，静默通过 `Promise.all` 批量拉取 `/fssc/expenseClaim/expenseRecordInvoice/getInvoiceByDataId`；
   - 将详情中的深度字段（`timeGetOn`、`timeGetOff`、`mileage`）保存在全局缓存；
   - 提取完成后静默触发一次行增强，原位在发票类型列注入 `⚠️ 缺乘车时间` 紧凑徽标，行添加柔和黄色警示底色，并高亮操作列【修改】。

### 2.2 查看与编辑发票弹窗深度增强 (`enhanceInvoiceDetailModal`)
1. **警示横幅注入 (`.yn-modal-alert-banner`)**：
   - 当用户打开发票查看或编辑弹窗（`.ant-modal-content`）时，自动扫描当前发票字段；
   - 若命中出租车缺失乘车时间，在弹窗顶部注入醒目警示横幅：  
     `【发票体检】该出租车发票未提取到上下车时间（显示为“-”），无法与考勤排期自动对齐行程，建议手动输入乘车时间后保存！`
   - 查看模式下提供 `✏️ 前往修改` 快捷跳转按钮。
2. **空字段标签与输入框原位高亮**：
   - 定位 `code="TIME_GETON"` 与 `code="TIME_GETOFF"` 表单块；
   - 在标签旁注入 `⚠️ 缺上车时间` / `⚠️ 缺下车时间` 徽标；
   - 编辑模式下为对应的空输入框注入黄色警示边框（`.yn-input-highlight-issue`），引导用户直接对照右侧发票原图将时间录入。

### 2.3 工具栏体检胶囊与过滤全面联动
- 工具栏胶囊文案动态显示：`发现 1 张残缺发票 (含12张缺乘车时间)`；
- 勾选「仅看残缺」时，自动将缺少金额等严重缺陷的发票与缺失乘车时间的出租车发票一并筛选出来，实现待办闭环。
