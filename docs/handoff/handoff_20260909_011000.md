## 1. 核心攻关与问题解决

### 1.1 用户反馈与质疑根本原因分析
用户在发票夹页面测试时提出两大关键质疑：
1. **“为什么所有出租车发票都提示缺少乘车时间，是不是没有使用发票详情接口批量检查？”**  
   - **根因查明**：旧代码误用了费用记录子模块的发票接口 `/fssc/expenseClaim/expenseRecordInvoice/getInvoiceByDataId`。在发票夹（BO 业务对象架构）中，此接口无法解包出租车业务数据，返回所有出租车专用字段均为 null，导致预取失效产生批量误报。
   - **真实接口纠偏**：经用户录制的系统真实交互 XHR 报文逆向分析，发票夹原生的详情接口为 `POST /fssc/bo/bodata/getBoDataAndTemplateWF`，入参为 `{ boMainId, scene: "VIEW", appId }`，返回的 `datas.TIME_GETON.value` 与 `datas.TIME_GETOFF.value` 100% 完备无损。
   - **真实数据验证断言**：在用户当前发票夹列表的 12 张出租车发票中，**11 张发票在系统底层实际完整具备乘车时间**（例如序号 1 为 `15:29 ~ 16:12`，序号 3 为 `09:40 ~ 10:07` 等），**仅有 1 张（序号 2：票号 33731480）真正缺少上下车时间**。旧逻辑的误报彻底清除！

2. **“还有开票日期错误没有提示（第一行 2002-07-27）”**  
   - **根因查明**：
     1. 旧校验规则中仅针对格式错误拦截，未对极端超期（如 2002 年，超期 24 年）的 OCR 识别失真发票设置阻断级错误；
     2. 在 `processTableRow` 的 DOM 徽标设置逻辑中，日期列徽标容易受单据综合状态影响被后续的 `removeBadge` 逻辑意外清除，导致未能原位显式呈现。
   - **解决方案**：
     1. 完善动态年份校验：基于 `new Date().getFullYear()` 动态推算，当开票年份早于当前年份 2 年以上时，自动升级为阻断级错误，短徽标定义为 `⚠️ 年份存疑`；
     2. 修复徽标独立渲染与防吞没：日期、金额、发票号、出租车乘车时间四个维度的徽标完全独立解耦判定，允许并存共显（如序号 1 同时展示 `⚠️ 年份存疑` 与 `⚠️ 缺金额`）。

## 2. 关键架构决策与技术落地

### 2.1 真实接口契约重构
彻底废弃发票夹对 `getInvoiceByDataId` 的调用，全面采用发票夹原生 BO 业务对象契约：
- **端点**：`POST /fssc/bo/bodata/getBoDataAndTemplateWF`
- **请求 Payload**：
  ```json
  {
    "boMainId": "row_data_id",
    "scene": "VIEW",
    "appId": "e3d5e4787ff911e88b1997bee3518b4d"
  }
  ```
- **数据提取路径**：
  `response.data.boData.area.rowDatas[0].datas`，统一提取：
  - `TIME_GETON.value`（上车时间）
  - `TIME_GETOFF.value`（下车时间）
  - `MILEAGE.value`（乘车里程）
  - `AMOUNT_TAX.value`（价税合计）
  - `INVOICE_NO.value`（发票号码）
  - `INVOICE_DATE.value`（开票日期）

### 2.2 请求头大小写与 EICDS 自适应安全管道
宿主系统在不同网络环境下（Axios/Fetch/XHR）可能发送全小写或驼峰请求头。本次更新在 `hookInvoiceDetailNetwork` 与 `prefetchTaxiDetails` 中实现大小写双向规范化匹配：
- 兼容捕获 `LoginToken` / `logintoken`, `EcsToken` / `ecstoken`, `eicds`, `appId`, `MenuId`, `UserOrigin`；
- 预取并发请求时完整带上安全认证凭据与 `eicds`，确保 100% 接口连通率与 0 鉴权失败。

### 2.3 状态机守卫与严格反硬编码规约
- **状态守卫**：出租车发票乘车时间校验增加 `detailChecked === true` 严格前置守卫，未完成接口详情预取前绝不提前误报；
- **反硬编码铁律**：开票日期超期判定完全基于动态日历 `new Date().getFullYear() - 2`，全代码库禁止任何特定发票号、特定日期或特定人名的写死判断。
