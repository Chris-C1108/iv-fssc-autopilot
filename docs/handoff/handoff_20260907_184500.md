## 1. 背景与问题诊断

### 1.1 现象分析（"啥也没输出？"）
在 WebMCP 交互过程中，用户上传了多张出差行程截图后，LLM 日志查看器显示模型连续调用了 6 次工具：
1. `fssc_get_applicant_context` (获取登录人信息)
2. `fssc_query_project` (查询项目)
3. `fssc_query_city` (查询目的地城市)
4. `fssc_query_employee` (查询 陈浩)
5. `fssc_query_employee` (查询 成勇)
6. `fssc_query_employee` (查询 李建勇)

随后对话直接停止，输出仅有纯文本：`"已完成多轮工具调用与综合规划。"`，聊天界面中未渲染出任何出差方案卡片、审批决策按钮，也无法启动自动填报。

### 1.2 根因定位 (Root Cause)
1. **硬编码轮次截断限制**：`src/services/llmService.ts` 中的 `maxRounds` 原设定为 `6`。由于模型在规划前期对登录人、项目、城市及 3 位人员逐个进行了串行单点维表检索，正好消耗完全部 6 个轮次配额，导致模型在即将调用最核心的 `fssc_plan_trip_applications` 工具前被强制退出循环。
2. **Prompt 缺乏维表合并指导**：旧版 System Prompt 未明确提示 `fssc_plan_trip_applications` 本身即具有自动维表检索与城市消歧能力，导致 Gemini 模型过度保守地逐个调用 `fssc_query_employee`。
3. **UI 缺乏防御性兜底**：`src/ui/webmcpModal.ts` 强依赖 `plannedConfigs`，当模型轮次耗尽未成功调用 `fssc_plan_trip_applications` 时，UI 仅显示了普通提示，没有主动触发多模态与日程启发式引擎兜底。

## 2. 核心架构变更与技术实现

### 2.1 工具轮次扩容至 15 轮 (`src/services/llmService.ts`)
- 将单次对话的 Agent 工具调用最大轮次由 6 轮提升至 15 轮（`let maxRounds = 15;`），为复杂跨维度分析（多附件、多同行人、项目查询、城市消歧、多单规划）提供充裕的思考与执行步数。

### 2.2 System Prompt 维表串行抑制与规划直达指引
- 在 System Prompt 中注入权威指引：
  - `fssc_plan_trip_applications` 底层全自动处理人员和城市模糊匹配与系统字典穿透；
  - 严禁为了查询每个同行人而连续发起多次串行的 `fssc_query_employee`；
  - 明确规划出差时**必须**调用 `fssc_plan_trip_applications` 落地结构化参数。

### 2.3 UI 智能防截断兜底守卫 (`src/ui/webmcpModal.ts`)
- 当模型因意外情况退出且未产出 `plannedConfigs` 时：
  - 系统智能检测用户输入是否包含出差规划意图或包含附件图片；
  - 若检测到规划意图，副驾立即自动唤起 `handleHeuristic5DFlow` 本地启发式行程解构引擎；
  - **100% 保证**出差行程方案决策卡片与审批确认闸门在界面完整展开，彻底杜绝“啥也没输出”的交互死胡同。
