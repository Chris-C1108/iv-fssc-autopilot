## 1. 本次迭代核心攻关与成果清单

针对用户提出的核心要求与审查指令：
1. **“我看到代码中有大量正则表达式匹配关键字，事发后符合代码不应该接管LLM agentic 擅长的部分，请自查”**

我们进行了全面的代码库自查、架构纠偏与工具集成：

### 1.1 彻底切除确定性代码对大模型 Agent 的越权篡改（Usurpation）
- **问题根因**：在 `handleLlmAgentFlow` 中，当大模型生成了对话式回复但未触发工具调用时，代码中曾存在一段后置 `else` 逻辑：使用 `isExpenseIntent = /发票|费用|.../.test(prompt)` 正则强行捕获用户输入，并暴力调用 `handleExpenseBatchPlanningFlow`。这直接践踏了大模型的自主认知与对话引导，导致界面闪烁、非预期的流程被强行唤起。
- **重构治理**：
  - 彻底移除了 `handleLlmAgentFlow` 中的 post-LLM 正则接管逻辑。大模型的文本回复得到 100% 尊重与呈现，仅追加操作芯片（`appendSuggestions`）供用户自主决定是否一键执行快捷流程；
  - 移除了 `catch` 异常分支中的正则暴力兜底，统一改为友好的卡片警示并呈现快捷指引，保障 Agentic 控制权的纯粹性。

### 1.2 全面清除私有实体硬编码与静态常识字典 (Anti-Hardcoding)
- **清剿员工姓名与代办人员**：
  - 彻底删除了 `李建勇|成勇|李工|张工|王工|陈浩` 等写死在正则中的员工姓名；
  - `proxyName` 提取严格基于通用前缀正则（如 `(?:外驻|代办|同事)[:：\s]*([^\s，,。]+)`），若用户未提供则保持为空字符串 `''`。
- **清剿默认客户与客户企业字典**：
  - 删除了默认 `customerName = 'CMP'` 的写死赋值，默认值重置为 `''`；
  - 删除了 `(CMP|住理工|积塔|长鑫|中芯|东海化成|津荣)` 等特定企业静态枚举正则；
  - 若用户未在 Prompt 中指定客户，系统绝不妄加猜测，而是通过声明式 A2UI 表单引导用户确认或输入。
- **清除静态机场与高铁站字典**：
  - 彻底删除了 `commuteService.ts` 中维护的 `周水子|双流|天府|滨海|新桥|白云|宝安|萧山|禄口|栎社|咸阳|江北|大兴|首都` 等静态机场名称列表；
  - 彻底删除了 18 家连锁酒店品牌的硬编码数组（`亚朵|全季|希尔顿|洲际...`）；
  - 落实 **“世界常识归大模型，通用结构交规则”**：由大模型运用其完备的地理常识自主识别城市对应的机场与高铁站，并在 `trips` 结构化参数中下发；规则层仅提取通用后缀（如 `机场|火车站|高铁站`）并使用 `${dest}机场 / ${dest}高铁站` 模板兜底。

### 1.3 WebMCP 全生命周期 CRUD 工具库集成与提示词加固
根据 `docs/api/YUANNIAN_API_REFERENCE.md` 权威规范，正式为智能副驾注册并暴露 4 个全新 WebMCP 工具：
1. **`fssc_delete_expense_records`**：
   - 映射接口：`POST /fssc/expenseClaim/expenseRecord/deleteExpenseRecordList`
   - 功能：批量软删除冗余或无效的费用记录至回收站，同步更新副驾内存池。
2. **`fssc_delete_bill_drafts`**：
   - 映射接口：`POST /fssc/bill/billdata/deleteBillByBillMainIds`
   - 功能：批量删除未提交的出差申请单或报销单草稿（`billMainIds`）。
3. **`fssc_delete_invoices`**：
   - 映射接口：`POST /fssc/expenseClaim/expenseRecordInvoice/invoiceBOListDelete`
   - 功能：从发票池彻底删除作废发票（`invoiceIds`），同步清理副驾内存池。
4. **`fssc_create_reimbursement_draft`**：
   - 映射接口：`POST /fssc/expenseClaim/billData/createBillDataAndTemplateByExpenseIdList`
   - 功能：从未报销费用记录批量生成报销单草稿，严格遵循【禁止自动提交铁律】（`commit: false`，仅存草稿入库）。

- **提示词与大模型认知层（`llmService.ts`）同步增强**：
  - 在 `SYSTEM_PROMPT` 中新增【反硬编码与世界常识认知铁律】章节，指导模型充分运用其世界常识推理交通枢纽与多波次 trips；
  - 详尽列出了四大模块全量 CRUD 工具列表、使用场景与协同流转规约；
  - 强化了人在回路（HITL）与【严禁调用任何提交接口】的最高安全红线。
