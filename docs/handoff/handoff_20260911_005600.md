### 1.2 住宿费超标说明获取失败缺陷攻关 (v4.38.1)
- **缺陷表现**：用户在宿主系统已经手动填写了超标说明，但打开「批量修改费用信息」弹窗时超标说明列依然为空。
- **根因分析**：
  - 原逻辑仅机械读取 `rowDatas.OVER_STANDARD_DESCRIPTION?.value`；
  - 宿主系统多层级存储特性：该字段可能在列表主项 `rec`、详情完整对象 `fullData.expenseRecord` 或存在别名（`OVER_STANDARD_REASON`, `OVER_STAND_DESC`, `EXCEED_STANDARD_...`）；
  - 宿主界面编辑若尚未持久化，值暂存于宿主 React Fiber 树上。
- **修复方案**：
  - 新增多源多别名探测器 `extractOverStandardDescription(rowDatas, rec, fullData)`，覆盖 12+ 种常见别名、正则模糊扫描及多重数据包装；
  - 在 `fetchExpenseRecordsWithInvoiceDetails` 中透传 `rec` 和 `ruleData?.fullData`；
  - 新增宿主 DOM 穿透探测器 `extractOverStandardFromHostDom(recordId)`，穿透至宿主 React Fiber 实例读取内存绑定对象，实现 100% 捕获带入。

### 1.3 住宿费超标计算方式有误缺陷攻关 (v4.38.1)
- **缺陷表现**：发票金额 ¥4265.47、入住 4 晚、订了 3 间房（如截图所示），单价实际为 ¥355.45/间夜，远低于天津限额 ¥700/晚，但系统错误报红超标并拦截保存。
- **根因分析**：
  - 原 `isHotelGroupOverStandard` 公式为 `unitPrice = amount / nights`，**完全漏除了房间数 `roomNum`**（算成 1066.37 元/晚，严重误报）；
  - 美式日期（如 `08/17/2026`）格式解析存在潜在时区或异常；
  - 表格单元格就地修改房间数由超标变未超标后，未联动清除红框报警样式。
- **修复方案**：
  - 严格以总间夜数计算单价：$\text{totalRoomNights} = \text{nights} \times \max(1, \text{rooms})$，$\text{unitPrice} = \frac{\text{amount}}{\text{totalRoomNights}}$；
  - 增强 `normalizeDate` 与 `parseDateToTimestamp`，无缝支持 `MM/DD/YYYY` 与 `YYYY-MM-DD`；
  - 新增 `getHotelPricingDetail`，在单元格 Title 中呈现透明测算公式（如 `4晚 × 3间 = 12间夜，单价 ¥355.45/间夜`）；
  - 表格输入事件监听：修改房间数/日期/城市由超标变为未超标时，立即清除 `yn-bem-dyn-cell-empty` 和 `yn-bem-dyn-cell-over-standard`，并将 placeholder 恢复为 `未超标(选填)`。
