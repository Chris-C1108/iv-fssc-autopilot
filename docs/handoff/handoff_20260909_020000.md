## 1. 核心攻关与问题解决

### 1.1 用户反馈与业务诉求
1. **“发票夹信息完备之后，从发票夹将发票生成费用：过路费发票可以和出租车发票合并在一个费用中（即一个有2张发票的费用），请理解这个逻辑，然后设计并测试在 webmcp 智能副驾中对话方式测试与验证”**；
2. **“我希望的场景是用户 prompt：‘将发票夹中\'未使用发票\'清单中所有发票逐条生成费用信息’，然后 agent 可以自动调用 webmcp 实现 逐条生成并 A2UI 询问用户‘发现有出租车发票同期的过路费是否合并生成？’，但不依靠硬编码特定场景逻辑实现”**；
3. **“目前看到你的测试结果 似乎未能在发票夹中分别 出租车与住宿等费用”**。

### 1.2 根本原因剖析 (Root Cause)
1. **分类误判的罪魁祸首——销售方列错位**：
   - 宿主系统 React Table Fiber 的底层数据源中，哈希键 `5f61a40f7a4411e9b0ed71c52a9d46e2` 实际是发票的**创建人 ID**（"陈浩（ITS）"），而不是销售方名称；
   - 真实的销售方（如“广州锦澜轩酒店管理有限公司”）存储在 `item.columnCode === 'SALES_NAME'` 的动态属性中；
   - 此前代码错将创建人当成销售方，导致 2026-07-31 的 ¥1580 增值税专用发票无法识别出酒店名称，在固有文本中被降级误判为出租车，进而错误地与同日过路费强行合并。
2. **确定性代码与大模型认知边界失调**：
   - 此前缺乏“发票全量逐条生成”场景下的标准 WebMCP 工具入参约定与 A2UI 决策状态机；
   - 工具未将 `hasConcurrentTolls` 与 `tollInquiryPrompt` 显式回传给大模型，导致副驾无法在自然语言流中主动向用户抛出标准询问。

### 1.3 终极工程化落地方案 (Zero-Hardcoding & Schema-First)
1. **动态销售方提取与分类加固 (`src/services/expenseService.ts` & `commuteService.ts`)**：
   - 实现通用的 `getColumnValue(record, columnCode)` 函数，动态按 `columnCode === 'SALES_NAME'` 与 `columnCode === 'PURCHASER_NAME'` 提取真实商户；
   - 在 `detectInvoiceCategory` 与 `bindTollsToTaxiExpenses` 中增加强类型白名单与大额/票种排除保护，专票、住宿、火车机票 100% 排除在出租车绑定候选池外；
   - 2026-07-31 的 ¥1580 专用发票被 100% 稳固识别为 `HOTEL`（住宿费（宿泊代）），彻底杜绝与过路费误合并。
2. **动态同期过路费通用对齐检测 (`src/services/commuteService.ts`)**：
   - 动态识别所有 `isTollInvoice(inv)`，并与同一天内的 `TAXI` 行程进行时间与路线通用对齐，零日期硬编码；
   - 输出 `hasConcurrentTolls: true`、`concurrentTollsCount: 4` 与 `tollInquiryPrompt: '发现有出租车发票同期的过路费是否合并生成？'`；
   - 支持 `options.mergeTollsWithTaxi` 三态（`undefined` 未决/等待用户选择、`true` 合并生成、`false` 独立单笔生成）。
3. **声明式 A2UI 双轨交互卡片 (`src/ui/webmcpA2Ui.ts`)**：
   - 在未决状态下，自动注入醒目黄色询问告警卡：**“❓ 发现有出租车发票同期的过路费是否合并生成？”**；
   - 提供双分支决策按钮：`[🛣️ 合并生成 (1笔费用含多张发票)]` 与 `[📄 独立逐条生成 (每张独立单笔)]`；
   - 点击后执行内存级动态重算，实时更新发票绑定关系与预览表格，并平滑切换为当前状态提示与改选按钮。
4. **WebMCP 工具链与 System Prompt 规范 (`src/services/webmcpService.ts` & `llmService.ts`)**：
   - `fssc_generate_expense_from_invoices` 支持全量规划（默认 `saveImmediately: false`，安全门禁刚性拦截自动提交）；
   - 在 System Prompt 中严格规约：大模型收到全量生成费用指令时，自动调用工具规划，并在工具返回 `hasConcurrentTolls: true` 时，在文本中醒目向用户发起标准询问并引导双轨决策。
