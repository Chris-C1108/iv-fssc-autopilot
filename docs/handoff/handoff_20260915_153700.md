## 2. 核心架构重构与底层演进

### 2.1 设置弹窗层级与样式首跳加载
- **问题根因**：
  1. `injectWebMcpStyles()` 仅在 `webmcpModal.ts` 初始化时调用，副驾直接唤起时缺少样式；
  2. 原 `.webmcp-settings-backdrop` 样式层级为 `z-index: 100020`，而批量修改全屏弹窗 `batchEditExpenseModal` 层级高达 `10000000`，弹窗被直接渲染在全屏大表格背面，导致“点击无效”。
- **解决方案**：
  - 在 `openWebMcpSettingsModal()` 函数入口处主动调用 `injectWebMcpStyles()`；
  - 将 `.webmcp-settings-backdrop` 提升至 `z-index: 10000050 !important;`，永远处于所有全屏弹窗的最顶层。

### 2.2 自动探测引擎 (`fetchAvailableModels`)
- **探测适配器矩阵**：
  1. **Google Gemini**：优先通过 OpenAI 兼容 `/models` 端点探测，失败时自动尝试 `generativelanguage.googleapis.com/v1beta/models?key=API_KEY`；
  2. **Ollama**：自动转换 Base URL 请求 `/api/tags` 获取本地部署模型；
  3. **标准 OpenAI 兼容**：请求 `/v1/models` 并自动过滤 embedding、tts、whisper 等非聊天模型；
  4. **容灾降级**：若远端接口受 CORS 拦截或请求失败，自动无缝降级加载各服务商官方主流推荐预设库。

### 2.3 模型选择三重响应式同步网络 (v4.66.1)
- **问题根因**：
  - 用户在设置弹窗勾选了 3 个模型（如 `gemini-3.8-flash-high`、`gemini-3.8-flash-low`、`gemini-3.8-flash-medium`）并保存，但由于默认模型 `gemini-3.8-flash-low` 保持未变，React `useEffect([selectedModel])` 未触发，且缺失跨组件事件通知与 Props 显式透传，导致聊天框下拉框保留旧状态。
- **解决方案**：
  1. **传输层全局广播**：`saveLlmConfig` 写入 localStorage 时主动触发 `window.dispatchEvent(new CustomEvent('autopilot:llm_config_changed', { detail: config }))`；
  2. **组件实时监听**：`AssistantChatPanel` 挂载事件监听器，接收广播并在 0ms 内即时更新本地配置状态；
  3. **Props 显式直传**：`batchEditExpenseModal.ts` 中的 `renderAssistantChat` 透传 `llmConfig: getLlmConfig()`；
  4. **Composer 动态兜底**：`AssistantComposer` 优先读取激活配置，确保存储或状态中的已勾选模型列表 100% 同步呈现在下拉选项中。
