## 一、本次交接演进清单与核心突破

### 1. 「✏️ 批量修改费用」入口全局独立浮动化 (`v4.61.1`)
- **根除 DOM 容器依赖缺陷**：
  - 此前按钮挂载在操作栏容器（`.platform-expenseclaim-expenseRecord-index__operate_record_btn_container--3Yccrbqk`），在页面处于特定状态或操作栏未就绪时入口不可见；
  - 重构为挂载于 `doc.body` 的**全局独立浮动按钮**（`#yn-floating-batch-edit-expenses`），固定位于视口右下角（`bottom: 24px; right: 24px`，`z-index: 99999`）；
  - 遵循用户明确指示：**浮动按钮纯粹作为脚本 UI 入口，不设额外数字角标**，避免后台轻量轮询开销；
  - 采用 Linear/Vercel 风格深色高斯模糊设计与微动效交互，同时保留操作栏内按钮以保持向下兼容。

### 2. 多状态费用查询与微状态标签展示 (`v4.61.1`)
- **打破仅查未报销限制**：
  - 费用查询核心接口 `queryExpenseRecordListApi` 与 `fetchExpenseRecordsWithInvoiceDetails` 的参数增加 `statusList: string[] = ['NO_REIMBURSE', 'REIMBURSING']`；
  - 默认同时拉取**未报销**与**报销中**的全部费用记录，便于用户对已有草稿单据或修改中的费用进行统一核对与再编辑；
- **表格列精细化微标签呈现**：
  - `ExpenseRecordGroup` 扩充 `status` 字段，并在数据聚合阶段保留真实报销状态；
  - 表格的「费用类型」单元格中引入彩色微标签（`.yn-bem-status-tag`）：
    - 🟢 未报销：`yn-bem-status-tag is-no-reimburse`
    - 🔵 报销中：`yn-bem-status-tag is-reimbursing`
    - ⚪ 已报销：`yn-bem-status-tag is-reimbursed`
  - 导出 CSV 逻辑中保留并输出真实的 `status` 字段。

### 3. 大交通确定性推断函数 `resolveTransportLabel` 与安全 Gate 阻断 (`v4.61.1`)
- **根治 `飞机/高铁 | (外驻:姓名)` 占位符污染**：
  - 原代码在排期表或发票无交通列时，无脑降级写入 `'飞机/高铁'`，进而被组装成非法班次 `飞机/高铁 | (外驻:陈浩)`；
  - 新增确定性推断函数 `resolveTransportLabel(rawFromSchedule, invoiceTypes)`：
    1. 优先提取排期或输入参数中的显式交通/班次；
    2. 无显式文本时，穿透扫描关联发票票种：仅飞机票 ➔ `飞机`；仅高铁/火车票 ➔ `高铁`；两者皆有 ➔ `飞机/高铁`；
    3. 缺乏任何凭证时，坚决返回 `''`（空字符串），严禁在底层猜测编造；
- **出差申请单安全 Gate 硬阻断**：
  - 在 `handleSaveDrafts` 保存草稿前置守卫中，对所有包含 SC 的 Trips 航段执行大交通非空校验；
  - 一旦发现航段大交通为空或未决，弹出 Toast 刚性阻断并抛出异常，绝不向系统持久化不确定数据；
  - 在 `createSingleTripApplicationApi` 底层组装 `F_FLIGHT` 航段时二次校验，彻底杜绝违规写库。
