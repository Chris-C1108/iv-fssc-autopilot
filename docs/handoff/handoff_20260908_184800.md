## 1. 业务背景与用户痛点

用户在操作元年云费控系统时遇到死锁故障：
1. **费用记录搜寻无果**：在发票夹查看到 4 张过路费发票（8-24 ¥18、8-27 ¥18、8-04 ¥32、7-31 ¥13）标记为“已生成费用”，但在费用记录列表中无论如何搜索都找不到（未报销费用总数为 0）；
2. **重新上传发票冲突**：用户试图在本地重新上传发票文件（如 `"D:\00_Clients_Library\客户项目2025\住友\住友理工调查\003.报销整理\李建勇\过路费 8-24.png"`），系统发票验真查重拦截报错“发票冲突”；
3. **界面操作死锁**：在发票夹 UI 试图删除时，单行操作列无删除按钮，顶层“批量删除”按钮置灰禁用；
4. **业务接口拦截报错**：直接调用官方发票删除接口 `/fssc/expenseClaim/expenseRecordInvoice/invoiceBOListDelete`，后端返回硬性拦截报错：`"该发票已报销，禁止删除"`；
5. **构建效率问题**：混淆构建耗时 1 分 37 秒，且终端被第三方库的 `@__PURE__` 注解警告严重刷屏。

## 2. 根本原因深度剖析 (Root Cause)

通过 `huashu-chrome` MCP 深度抓包与底层数据库字段比对，彻底查明死锁根因：

### 2.1 元年云数据完整性缺陷（删除操作未级联反写）
- **记费用阶段**：发票生成费用记录时，系统向发票表写入了下游 `INVOICE_DATA_SOURCE_ID` 和 `INVOICE_DATA_SOURCE_TYPE: "EXPENSE_RECORD"`；
- **删费用阶段**：当下游费用记录被删除（通过 UI 删除或 API 彻底粉碎）后，**元年云后端事务仅删除了费用记录表中的行，遗漏了反向清空发票表中 `INVOICE_DATA_SOURCE_ID` 的逻辑**。

### 2.2 环环相扣的四重死锁
1. **前端展示误导**：发票列表检查到 `INVOICE_DATA_SOURCE_ID` 非空，强制渲染蓝字“已生成费用”；
2. **UI 权限拦截**：前端基于“已生成费用”判定发票已被下游单据占用，禁用并隐藏了删除按钮；
3. **业务层 API 拦截**：`invoiceBOListDelete` 业务接口同样校验该字段，报错“该发票已报销，禁止删除”；
4. **防重验真拦截**：重新上传图片时，系统检测到发票号码/代码已在库中，报错“发票冲突”。

### 2.3 全量发票池排查结论
排查全量 207 张发票，确认除正常绑定在真实报销单（如 `BJ25100097` 等）的发票以及未使用的发票外，**全系统仅有且仅有这 4 张发票处于该 Ghost Orphan 悬挂死锁状态**。

### 3.1 突破业务接口拦截：BO 底座接口强制物理删除破局

### 3.2 智能副驾发票删除自愈降级架构升级 (`src/services/expenseService.ts`)
在 `deleteInvoiceBOListApi` 中落地双层容灾重试策略：
```typescript
export async function deleteInvoiceBOListApi(invoiceIds: string[], state: GlobalState): Promise<any> {
    if (!invoiceIds || invoiceIds.length === 0) return { success: true };
    try {
        const res = await apiRequest('/fssc/expenseClaim/expenseRecordInvoice/invoiceBOListDelete', 'POST', invoiceIds, state);
        if (res && res.success) return res;
    } catch (e: any) {
        // 捕获“该发票已报销，禁止删除”异常，无缝降级至 BO 底座物理删除
    }
    for (const id of invoiceIds) {
        await apiRequest('/fssc/bo/bodata/deleteBoByBoMainId', 'POST', `boMainId=${encodeURIComponent(id)}`, state, true);
    }
    return { data: [], message: '删除成功！', success: true };
}
```

### 3.3 Rollup 警告静音与 12 倍极速构建 (`rollup.config.mjs`)
1. **`onwarn` 过滤钩子**：针对第三方库中无效的 `/* @__PURE__ */` 注解警告实施静音过滤，终端输出恢复清爽；
2. **默认禁用高强度混淆**：引入 `const ENABLE_OBFUSCATION = process.env.OBFUSCATE === 'true';`，默认关闭耗时的混淆流程；
3. **构建提速**：构建耗时从 **1分37秒骤降至 8.1秒**（提速 12 倍），油猴脚本 Banner 元数据保持 100% 完整无损。
