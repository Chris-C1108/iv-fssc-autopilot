## 1. 缺陷背景与根因定位

### 1.1 问题复现
用户在批量修改费用信息模态框的 AI 智能副驾中发送：
> 「读取未提交的报销单 整理费用备注中的 人名，整理并列出每个人的报销金额 /list」

**副驾原回复表现**：
- 识别出了 7 张报销单草稿中的 20 笔费用明细与 3 位人员（李建勇、陈浩、成勇）；
- **致命缺陷 A**：所有报销单草稿以及明细行的金额全部显示为 `¥0.00`；
- **致命缺陷 B**：用户当前模态框中共有 **119 笔全量待报销费用**，但原逻辑仅向后台查询了草稿箱中已创建的 7 张单据（仅含 20 笔费用），导致其余 99 笔待报销费用直接断层遗漏，严重脱节用户的真实对账基准。

### 1.2 根因深度剖析
1. **根因 A (报销单明细行金额字段形态不一)**：
   - 元年云报销单明细行（`claimSubAreaId = 3bfd939291eb42439b692181c5477a96`）中，不同单据模板与草稿阶段下的金额字段形态各异：
     - 部分模板仅填写了 `F_BCHSZJ`（本次核算总计/本次报销总计）；
     - 部分草稿刚由费用生成，明细行自身的 `AMOUNT.value.amount` 为 0，真实金额保存在 `recArea`（支出记录区 `7e1debbe739248c4a49ea98088997acf`）或预算区 `boArea`（`203d2e64f6bd4b32a8c83d030fb32676`）；
     - 原代码仅盲目读取 `claimDatas.AMOUNT?.value?.amount`，未做多级防御性回退，导致解析出的金额全为 0。
2. **根因 B (业务场景与数据源断层)**：
   - 用户虽然使用了“读取未提交报销单”这种自然语言表述，但其核心财务诉求是“整理费用备注中的人名与每个人的报销金额”；
   - 用户在打开批量修改模态框时，大表格中承载的是全量 119 笔费用记录池（已打标 `[外驻:李建勇]`、`[陈浩]` 等），真实账目为：
     - **陈浩 ITS**：54 笔，64 张发票，合计 ¥25,557.87
     - **李建勇**：48 笔，53 张发票，合计 ¥16,403.00
     - **成勇**：17 笔，17 张发票，合计 ¥13,409.00
     - **总计**：119 笔费用，134 张发票，总金额 ¥55,369.87
   - 原代码只要匹配到“未提交”或“报销单”，就直接抛弃当前 119 笔全量费用池，只向后台查询 7 张残缺草稿单，造成断层。

## 2. 解决方案与核心改动

### 2.1 架构升级：双轨财务汇算与穿透体系
1. **多级防御性金额抽取器 (`extractRowAmount`)**：
   - 位于 `src/services/billService.ts`；
   - 级联优先级：
     ① 优先读取明细行 `claimDatas` 中的 `AMOUNT`、`F_BCHSZJ`、`AMOUNT_TAX`、`TOTAL_AMOUNT`、`EXPENSE_AMOUNT` 等；
     ② 穿透读取 `recArea`（支出记录区）的 `rowDatas[0].datas.AMOUNT`；
     ③ 穿透读取 `boArea`（预算区）的 `rowDatas[0].datas.BUDGET_SUM` / `AMOUNT`；
     ④ 遍历 `claimDatas` 中所有带金额特征的字段；
     ⑤ 兜底读取单据主表 `SUM_AMOUNT` / `F_HJTOTA`；
   - 杜绝任何单据草稿金额归零。
2. **全量待报销费用池确定性人员账目报表 (`generateComprehensivePersonExpenseReport`)**：
   - 纯确定性、高性能、无大模型幻觉算法，严格遵守 `AGENTS.md` 反硬编码铁律（无任何写死人名、工号、金额）；
   - 正则动态提取 `\[(?:外驻[:：])?([^\]]+)\]`，自动区分外驻人员与本部社员；
   - 按照费用笔数、发票张数（按 `g.invoices.length` 累加多发票合并）、累计金额汇总；
   - 生成标准财务 Markdown 总表与展开式各人员明细清单 (`/list`)。
3. **双轨数据融合调度**：
   - 在 `src/ui/batchEditExpenseModal.ts` 的 `handleAssistantSendMessage` 中：
   - 当用户发起人名整理、金额统计或报销单查询时，同时呈现：
     - **层次一**：【📊 全量待报销费用·各人员归集对账总表】（精准对齐手工账 119 笔 ¥55,369.87）；
     - **层次二**：【📋 各人员费用明细清单 (/list)】；
     - **层次三**：【📑 系统后台已创建未提交报销单草稿流转状态】（修复金额后的草稿单状态）。
   - 离线状态（无 API Key）直接输出该完美报表；在线状态（有 API Key）大模型严格基于该数据源呈现专业解读。
