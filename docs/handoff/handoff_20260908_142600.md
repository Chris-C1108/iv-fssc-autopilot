### 1.2 CRUD 完备性检验结论
经实测证明，智能副驾在四大模块上的增删改查全流程已 **100% 具备且全部连通**：
- **C (Create)**：支持发票 OCR 上传、费用记录生成、空白申请单立项、费用记录批量生成报销单草稿；
- **R (Read)**：支持发票池检索、底层 OCR 字段穿透挽回、15 类费用树、单据 9 大区域读取与历史防重网格；
- **U (Update)**：支持 33 槽位初始化、附件挂载、行程说明规范化、预算三步联动、关联申请单回写、出差报告回填与 30 倍极速保存；
- **D (Delete)**：支持发票彻底删除 (`invoiceBOListDelete`)、费用记录软删除/回收站还原 (`deleteExpenseRecordList`)、单据草稿删除 (`deleteBillByBillMainIds`)。

### 1.3 【禁止自动提交铁律】全栈四重刚性防御加固
针对用户提出的“禁止调用 API 提交按钮接口，只允许调用保存按钮接口”铁律，实施了全栈闭环加固：
1. **底层 HTTP 传输网关刚性守卫 (`src/utils/http.ts`)**：
   - 在核心网络通信函数 `apiRequest` 入口处设立硬编码拦截：凡 URL 包含 `/submitBillData`、`/flow/runtime/commit`、`/submitBill` 直接刚性拦截并抛出异常；
   - 增加自动重写防御：凡单据保存 Payload，若误传 `commit: true`，底层代码自动刚性重写为 `commit: false`，彻底消除误提隐患。
2. **大模型认知决策层强约束 (`src/services/llmService.ts`)**：
   - 在 `SYSTEM_PROMPT` 顶部注入最高优先级红线规约：明确副驾只允许调用【保存】接口（`saveBillData`，草稿入库），严禁调用任何【提交】审批流接口，提交动作必须严格留给用户在页面上人工复核后手动点击。
3. **WebMCP 工具定义与 UI 文案纠偏 (`src/services/webmcpService.ts`, `src/ui/webmcpModal.ts`, `src/ui/webmcpArtifactView.ts`)**：
   - 将 `fssc_create_trip_draft` 工具描述中的“提交创建...”修正为“保存创建单张出差申请单草稿（commit: false，仅保存草稿入库，绝不提交审批）”；
   - 将全景看板和审批门禁按钮统一修正为：`✅ 批准并保存入库草稿 (Save Draft)`，明确向用户传达“仅入库草稿，不发起审批”的操作边界。
4. **权威文档永久收录 (`AGENTS.md`, `docs/api/YUANNIAN_API_REFERENCE.md`)**：
   - 在 `AGENTS.md` 职责划分矩阵中增加【禁止自动提交铁律】；
   - 在 `YUANNIAN_API_REFERENCE.md` 申请单与报销单提交接口处增注醒目的 `🚫【副驾安全红线禁令】` 警示徽章。
