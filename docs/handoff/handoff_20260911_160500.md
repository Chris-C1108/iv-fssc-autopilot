## 1. 本次工作背景与核心痛点彻底清剿 (Context & Problem Elimination)

用户反馈：在打开「批量修改费用信息」模态框时，直观感受界面极度杂乱、视觉窒息（*"说不上来为什么，但是这个界面设计太垃圾了"*）。经严谨的界面工程剖析，定位到以下四个深层根因并实施了彻底根治：

1. **表格有效高度被严重挤压 (40% 屏幕空间浪费) ➔ 移出 DOM 流，独立弹窗化**：
   - **痛点**：旧版顶部挤占了双行操作栏，外加一个展开高达 220px 的批量设置表单面板（7 个输入框、格式预设、模版说明等），导致下方的核心数据表格被压缩成窄长条，用户查看与编辑数据极其局促；
   - **重构方案**：将批量设置完全移出主 DOM 流，重构为点击即呼出的居中专注弹窗（`openBatchSettingsDialog` / `.yn-bem-batch-dialog`，宽度 720px，三卡片分区组织），主界面仅保留 44px 极简顶栏与 34px 紧凑状态条，表格可视高度瞬间恢复至 88% 以上。

2. **35 列平铺造成的“横杠荒漠” (Empty Dash Desert) ➔ 精简核心列 + 行程微胶囊**：
   - **痛点**：旧版表格 flat-render 了全部 35 列（6 个基础列 + 15 个各类型动态列 + 14 个发票子列），导致出租车、误餐、通信等单据在 7~16 列全部显示为空横杠（`- - - - - -`），需要不断横向滚动；
   - **重构方案**：缺省启用 `viewMode: 'CLEAN'`（精简核心列），将 35 列大幅收敛为 **9 个人性化核心列**：
     `[☑]`, `最早开票日`, `费用业务日期`, `费用类型`, `行程与明细胶囊`, `金额`, `费用说明`, `发票`, `操作`；
     通过 `getGroupRouteDetailsHtml` 将复杂的飞机航线（`✈️ 上海 ➔ 北京 (CZ6534)`）、高铁班次（`🚆 虹桥 ➔ 南京南 (G12)`）、出租车始发目的地（`🚕 酒店 ➔ 客户据点`）、酒店（`🏨 亚朵酒店 (天津市 · 07-20~07-24)`）、通信账期以精致优雅的微胶囊呈现，缺失时显示 `+ 补充行程` 点击直接呼出行级专属弹窗；彻底根除了横向滚动的疲劳，同时保留 `全量35列 (FULL)` 作为一键切换视图。

3. **四角割裂无焦点的“九宫格乱局” ➔ 现代底部悬浮操作岛 (Floating Action Island)**：
   - **痛点**：控制按钮散落在左上、右上、左下、右下，视线反复跳跃；
   - **重构方案**：参考 Linear、Stripe、Vercel 设计范式，引入 **现代底部悬浮操作岛 (`.yn-bem-floating-island`)**：
     - 未选中时自然向下滑出屏幕（`translateY(30px); opacity: 0; pointer-events: none`）；
     - 勾选条目时弹性浮现于底部正中央，毛玻璃暗黑微透背景（`rgba(24, 24, 27, 0.94); backdrop-filter: blur(16px)`），显示选中项数与金额统计，并集成 `⚙️ 批量修改属性`、`✨ AI智能推断`、`📥 导出`、`💾 批量保存` 与 `✕ 清选` 胶囊按钮，为用户提供极其明确的视觉重心与行动召唤 (CTA)。

4. **粗笨 Textarea 撑大行高 ➔ 极简单行 Input (`.yn-bem-desc-input`)**：
   - **痛点**：旧版费用说明使用粗笨的带缩放三角的 textarea，导致各行高度参差不齐；
   - **重构方案**：在精简模式下使用 30px 高度、去除 resize 三角的单行输入框，按 Enter 或 Tab 平滑流转，保障表格各行保持统一严谨的 38px 财务等宽排版节奏。
