# 交接文档 — 表格 UI 故障排查与全量修复 (v4.48.0)

> **交接时间**：2026-09-11 17:52:00  
> **基准版本**：`v4.48.0`  
> **关联任务**：解决大表格列宽崩溃（多列被压缩为 0px）、表头内容错位重叠、以及单元格内输入框尺寸未 100% 满高满宽贴合问题。

---

## 1. 故障根因与修复总结

### 1.1 根因剖析
1. **未设置宽度的列在 `table-layout: fixed` 下被压缩为 0px**：
   `COLUMN_DEFINITIONS` 中有 16 列缺失 `width` 属性。在固定布局下，浏览器表格算法将未定宽的列直接压缩为 0px，导致最早开票日、业务日期、费用类型、费用金额、发票张数等关键列全部消失，单元格内容横向严重溢出穿透；
2. **缺失 `<colgroup>` 规范声明**：
   在拥有多级分组小计跨列行 (`colspan="36"`) 的场景下，缺少 `<colgroup>` 锁死列网格，布局极易混乱；
3. **表格样式写死 `width: 100%`**：
   将总计约 4080px 的 36 列强塞入 1920px 视口，导致浏览器牺牲无宽度的列；
4. **单元格输入框尺寸不一致**：
   第 1204 行存在覆盖样式 `.yn-bem-cell-interactive { padding: 3px 6px !important; }`，导致单元格内部留有空隙；且业务日期输入框写死 `width: 122px`，未实现现代无缝电子表格贴合效果。

### 1.2 修复举措
1. **全量补全 35 列显式宽度**（`src/ui/batchEditExpenseModal.ts`）：
   明确设定各列宽度（从 50px 到 280px），保障固定布局下的稳定性；
2. **在主表及空状态表中注入 `<colgroup>`**：
   使用 `<col style="width:...; min-width:...;">` 刚性锁定表格 36 列几何尺寸；
3. **调整表格宽度模型**（`src/ui/batchEditExpenseStyles.ts`）：
   设置为 `min-width: 100%; width: max-content; table-layout: fixed;`，平滑交由外层容器实现横向滚动；
4. **单元格输入框 100% 满高满宽贴合**：
   - 移除覆盖性 padding，确保 `td.yn-bem-cell-interactive` 为 `padding: 0 !important; vertical-align: middle !important; height: 100% !important;`；
   - 改造 `.yn-bem-cell-date-input` 为 `width: 100%; height: 100%; min-height: 34px; border-radius: 0;`，聚焦时呈现内嵌边框；
   - 保持业务日期单元格结构紧凑，将变更提示移入 `title` 气泡与状态背景色中。
