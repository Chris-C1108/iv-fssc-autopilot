## 1. 本次迭代核心解决的问题清单

针对用户反馈的 5 项核心问题进行专项攻关与全面修复：

1. **交通工具备注格式重复 (消除多重姓名)**：
   - **问题**：交通工具标签出现重复人名，如 `MU5227 | (陈浩) (陈浩)`、`MU5227 | (外驻:成勇) (成勇)`。
   - **修复**：对格式化逻辑进行规范清洗，若班次字符串已包含出差人员姓名，不再二次拼接 `(姓名)`，确保标签统一为 `MU5227 | (陈浩)` 或 `飞机/高铁 (李建勇)`。
2. **四项费用展示计算逻辑透明化**：
   - **问题**：交通+改签、酒店住宿、误餐补贴、市内Buffer 原先只展示汇总数字，未公开明细单价与折算逻辑。
   - **修复**：引入 `TripFeeFormulas`，全面记录并直观渲染：
     - **大交通**：`3人往返大交通基准 (¥0/人) + 改签弹性15% (¥0) = ¥0`；
     - **酒店住宿**：`3人住用合计 (二三线限额¥700/晚，共11间夜) = ¥7,700`；
     - **误餐补贴**：`3人差旅生活补贴 (往返乘车日各半额¥150，整天调研¥300) = ¥3,300`；
     - **市内Buffer**：`3人市内出租/网约车预留Buffer (¥100/人/天) = ¥1,400`；
     - **总预算公式**：四项汇总公式，单据卡片、全景看板与详情弹窗全覆盖。
3. **人员差异化出发/返程识别 (李建勇 7/21 出发、陈浩 8/20 提前返程)**：
   - **问题**：原行程推断将所有人统一绑定为相同的起止日期，未能反映李建勇延后一天 (7/21) 出发、陈浩提前一天 (8/20) 返程的真实日程。
   - **修复**：日程解析引擎对每位出差人员建立独立活跃时间线映射 `travelerPeriods.set(t, { start, end })`：
     - **Trip 1 (天津)**：陈浩/成勇 7/20 出发，李建勇 7/21 出发（生成独立 Leg #3）；
     - **Trip 5 (天津)**：陈浩 8/20 返程（Leg #4），成勇与李建勇 8/21 返程（Leg #5, #6）；
     - 住宿晚数、餐补天数和市内Buffer按个人实际日程分别核算后累加。
4. **与历史已保存/已提交单据交叉比对 (防重复填报)**：
   - **问题**：分析与提交未对比系统已保存的历史单据（`ync37.yuanian.com-002-经费报销单页-历史.har`）。
   - **修复**：接入 `POST /fssc/billViewConfig/getBillViewQueryDataList` 接口；
     - 新增 WebMCP 工具 `fssc_query_historical_applications`，并在规划阶段自动拉取历史申请单比对目的地和起止日期；
     - 发现重叠时自动标注警告徽章（如 `⚠️ 发现历史单据: SC26090021 (已保存)`），防止重复填报。
5. **单据入库后旅程明细为空修复 (截图4 核心 BUG)**：
   - **根因**：元年草稿模板中子表 `T_BILL_AREA_CCS_DEF_001` 的 `datas` 对象未初始化 `F_DATE`、`F_FROM`、`F_TO`、`F_FLIGHT`，原代码因 `if (row.datas.F_XYZ)` 判断为 falsy 而跳过了字段赋值；此外日期带有秒时无法被元年 UI 解析。
   - **修复**：强制采用 `ensureRowField` 动态补齐字段对象元数据；日期格式严格规范为 `YYYY-MM-DDTHH:mm`（16位，精确到分，无秒）；并在提交前将 `generatedLegRows` 挂回 `billData.area.rowDatas[0].subAreaDatas`，确保 100% 成功入库。
