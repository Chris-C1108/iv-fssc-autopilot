## 1. 任务背景与问题诊断 (Problem & Diagnosis)

### 1.1 用户反馈问题
- 用户按 AI 推断结果保存费用记录后，页面刷新，宿主页面已正确展示保存后的业务数据（说明后端持久化接口 `saveFinalExpenseRecordApi` 写入成功）；
- **但当用户再次打开「批量修改费用信息」模态框时，表格中依然显示大量必填字段缺失（红框标红警告）**，包括：
  - 住宿费：入住日期（checkInDate）、离店日期（checkOutDate）、出差城市（city）、住宿城市类型（cityType）全部为空；酒店名称重置为发票销方公司抬头；
  - 飞机票：起程日期、到达日期、出发地、到达地、航班号全部标红为“必填”；
  - 出租车：打车始发地、打车目的地全部为空。
- 视觉呈现“就像完全没有保存过一样”，严重破坏用户体验与操作连贯性。

### 1.2 根本原因剖析 (Root Cause Analysis)
1. **数据抽取层信息丢弃 (Data Loss in `fetchExpenseRecordsWithInvoiceDetails`)**：
   - 提取费用记录时，系统调用了 `getExpenseTypeRuleAndRowDatasApi(rec.expenseRecordId, ...)`，后端成功返回了该笔费用已入库的完整 `ruleData.rowDatas`（包含已保存的 `CHECK_IN_DATE`、`CHECK_OUT_DATE`、`CITY`、`F_ZSC_DEF_001`、`HOTEL_NAME`、`ROOM_NUM`、`FLIGHT_START_DATE`、`FLIGHT_FROM_CITY`、`FLIGHT_TO_CITY`、`START_ADDRESS`、`END_ADDRESS` 等所有数据）；
   - **但旧代码仅读取了 `ruleData.rowDatas.expenseRecordInvoiceList`（发票附件），将其余所有已保存字段全部丢弃**，导致构造的 `ExpenseRecordExportRow` 根本不包含任何已保存的动态字段！
2. **弹窗聚合层空值强制覆盖 (Forced Empty Overwrite in `groupExpenseRows`)**：
   - 在 `batchEditExpenseModal.ts` 中，`groupExpenseRows()` 初始构造 `ExpenseRecordGroup` 时未从 `r` 中读取任何动态字段；
   - 且针对住宿费（`HOTEL`），旧代码硬编码执行了：
     ```typescript
     g.dynamicFields.checkInDate = ''; // 硬编码清空
     g.dynamicFields.checkOutDate = ''; // 硬编码清空
     g.dynamicFields.hotelName = inv0.salesName.replace(...); // 发票抬头强制覆盖干净酒店名
     g.dynamicFields.roomNum = 1;
     // city 甚至未赋值，保持 undefined
     ```
   - 针对出租车（`TAXI`）仅读取了电子发票中通常为空的 `inv0.stationGetOn`，导致打车始发/目的地为空；
   - 针对飞机票（`FLIGHT`）仅从发票 OCR 兜底，丢弃了数据库已有的起止城市与航班号；
   - **结果**：重新打开弹窗时，已有数据库数据被重置为空字符串，触发了各必填字段标红。

## 2. 核心架构改造与技术方案 (Technical Solution)

### 2.1 全量已保存字段逆向提取器 (`extractSavedDynamicFields`)
在 `src/services/expenseService.ts` 中新增高容错通用提取算法：
- **`extractDropdownText(val)`**：自适应处理元数据中各种复杂下拉对象（兼容 `title.zh_CN`、`label`、`name`、非 HexID 的 `value`）；
- **`extractDateOnly(val)`**：将元年云 ISO/带时间字符串（如 `2026-07-21T00:00`、`2026-07-21 00:00:00`）标准化为 HTML5 `<input type="date">` 所需的 `YYYY-MM-DD` 格式；
- **`extractSavedDynamicFields(rowDatas)`**：全面提取并映射：
  - 住宿费：`CHECK_IN_DATE` ➔ `checkInDate`, `CHECK_OUT_DATE` ➔ `checkOutDate`, `CITY` ➔ `city`, `F_ZSC_DEF_001` ➔ `cityType`（若缺失则根据城市规则自动联动补全 `境内-北上广深` / `境内-其他`）, `HOTEL_NAME` ➔ `hotelName`, `ROOM_NUM` ➔ `roomNum`；
  - 飞机票：`FLIGHT_START_DATE` ➔ `flightStartDate`, `FLIGHT_END_DATE` ➔ `flightEndDate`, `FLIGHT_FROM_CITY` ➔ `flightFromCity`, `FLIGHT_TO_CITY` ➔ `flightToCity`, `FLIGHT_NUM` ➔ `flightNum`；
  - 火车票：`TRAIN_START_DATE` ➔ `trainStartDate`, `TRAIN_END_DATE` ➔ `trainEndDate`, `TRAIN_FROM_CITY`/`START_ADDRESS` ➔ `trainFromStation`, `TRAIN_TO_CITY`/`END_ADDRESS` ➔ `trainToStation`, `TRAIN_NUM` ➔ `trainNum`；
  - 出租车：`START_ADDRESS` ➔ `startAddress`, `END_ADDRESS` ➔ `endAddress`；
  - 通信费：`BILL_MONTH`/`F_ZY_DEF_001` ➔ `billMonth`。

### 2.2 数据模型扩展 (`ExpenseRecordExportRow`)
在 `ExpenseRecordExportRow` 契约中扩展：
```typescript
savedDynamicFields?: DynamicExpenseFieldValues;
savedRowDatas?: any;
```
并在 `fetchExpenseRecordsWithInvoiceDetails` 的 `baseRowInfo` 中完成挂载透传，同时在超时/异常 catch 块中做好空对象保底防御。

### 2.3 弹窗聚合层“优先继承入库字段，仅对空缺执行 OCR 兜底”
在 `src/ui/batchEditExpenseModal.ts` 中重构 `groupExpenseRows`：
1. **初始化继承**：构造 `ExpenseRecordGroup` 时直接浅克隆 `r.savedDynamicFields`：
   ```typescript
   dynamicFields: r.savedDynamicFields ? { ...r.savedDynamicFields } : {}
   ```
2. **多发票合并继承**：针对同一费用绑定的后续发票行，合并动态字段并补齐 `newStartAddress`/`newEndAddress`；
3. **安全兜底非破坏性回填**：仅当特定字段在数据库中未保存或为空时，才回落到发票第一张票 `inv0` 的 OCR 数据（如 `if (!dyn.flightFromCity && inv0?.stationGetOn)`），严禁执行任何无条件置空或发票抬头覆盖已有干净名称的操作。
