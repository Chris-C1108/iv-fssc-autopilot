## 一、本次交接演进清单与核心突破

### 1. 意图路由器分流解耦 (`isBillAutoFill` 精细化收敛)
- **消除误拦截陷阱**：此前 `handleAssistantSendMessage` 凡遇到包含“报销单”、“申请单”文本，一律强行拦截并执行 `isBillAutoFill`（一键补全工作台），导致用户查询诉求被错误转为动作执行；
- **增设查询守卫 `isQueryIntent`**：
  ```typescript
  const isQueryIntent = /查询|查看|读取|列出|整理|统计|汇总|分析|搜索|清单|明细|每个人|谁的|金额|多少|有哪些|发票列表|账目/.test(lowerText);
  const isBillAutoFill = !isReportIntent && !isQueryIntent && (lowerText.includes('补全') || lowerText.includes('自动填') ...);
  ```
- 确保所有带有“读取/查看/列出/整理”等只读诉求的指令畅通流转至通用问答与查询分析通道。

### 2. 未提交报销单草稿底层明细穿透提取 (`fetchUncommittedReimbursementBillsSummary`)
- 在 `src/services/billService.ts` 中实现通用服务函数：
  1. 调用 `/fssc/billViewConfig/getBillViewQueryDataList` 检索当前登录人全部“未提交”报销单（草稿态）；
  2. 遍历拉取到的草稿单（如 `BC` 出差报销单），调用 `/fssc/bill/billdata/getBillDataAndTemplateByBillMainId` 提取单据内部明细区全部费用行；
  3. 提取每行的行号、费用类型、金额（`AMOUNT`）、事由备注说明（`recDesc`）并智能提取出行人人名标签（`[外驻:成勇]`、`[陈浩]` 等）；
  4. 汇总为标准 Markdown 数据表格。

### 3. 通用查询数据源按需动态挂载与大模型/离线双通道支持
- **按需动态挂载**：
  - 若用户指令涉及“报销单/申请单/草稿/未提交”，自动实时穿透拉取草稿单据内部行数据；
  - 若涉及当前界面费用明细，自动将 `modalState.groups` 压缩投影为紧凑 Markdown 数据表格；
- **大模型精准解答**：
  - 将真实业务数据源注入 `systemPrompt`，指示大模型严格基于真实数据源以清晰 Markdown 列表/表格输出，列出人名、单号/费用项、金额与备注说明；
- **离线安全兜底**：
  - 在未配置大模型 API Key 时，副驾直接在对话流中输出提取到的全量结构化数据表格清单，保障功能绝对可用。
